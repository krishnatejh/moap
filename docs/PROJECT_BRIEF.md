## Problem

_The specific pain this project exists to remove. Not a solution — the problem and who has it._

## Users

_Who uses this, what they are trying to do, and what they already know. Include any distinction between primary and secondary users._

## Desired outcome

_What is true when this has succeeded. Describe the result the user can observe, not the features that deliver it._

## Non-negotiables

_Constraints that cannot be traded away without human approval. Budget limits, platforms that must be supported, data that cannot leave a boundary, regulations, existing systems that must not break._

<!-- Example:
- Must run on a machine with no cloud subscription.
- Customer data must never leave the user's own device.
- Must work on Windows, macOS, and Linux.
-->

## Explicitly out of scope

_What this project will deliberately not do in its first phase. Prevents scope creep and makes descoping a legitimate option instead of a failure._

## Success criteria

_How the human will judge whether this worked. Behaviour the human can see or use, not implementation detail._

<!-- Example:
- The human can add a transaction by hand and see it in a monthly total without any manual editing.
- The app starts with one documented command on a clean machine.
-->

## Assumptions

_Material details the human did not specify, where the orchestrator chose a default. Each must be confirmed or corrected at kickoff._

<!-- Example:
